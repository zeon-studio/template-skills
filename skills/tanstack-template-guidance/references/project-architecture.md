# Project Architecture

This skill provides a high-level map of the TanStack Start template ecosystem — a full-stack, router-first React framework built on TanStack Router, bundled with Vite (or Rsbuild).

## The one thing to understand first

**Most of the framework is the route tree.** Routes, params, search schemas, loaders, pending states, links, and navigation all come from TanStack Router. TanStack Start adds the server layer around it: SSR, streaming, and server functions.

Unlike Astro (Content Collections) or Hugo (content/layout pairing), **TanStack Start ships no built-in content layer**. Markdown support is whatever the template wired up — see `references/content-management.md`.

> [!IMPORTANT]
> **Architecture Verification Required:** Because this skill is used across multiple templates, the directory structures below are **JUST EXAMPLES**. The actual architecture varies per template. **You MUST ALWAYS verify the project structure by listing the root directory and `src/` before assuming where files live.**

## Example Folder Structure (Verify Before Use)

```text
├── .agents/skills/        # AI Agent skills (like this document)
├── public/                # Static assets served at the web root (images, fonts, favicon)
├── src/
│   ├── routes/            # File-based routes — the heart of the app
│   │   ├── __root.tsx     # Root layout wrapping every route
│   │   ├── index.tsx      # "/"
│   │   └── blog/
│   │       ├── index.tsx  # "/blog"
│   │       └── $slug.tsx  # "/blog/:slug"
│   ├── routeTree.gen.ts   # AUTO-GENERATED route tree — never edit
│   ├── router.tsx         # Router instance creation/config
│   ├── components/        # Reusable UI components
│   ├── content/           # Markdown/MDX content (if the template uses local content)
│   ├── config/            # Global JSON configuration files
│   ├── lib/               # Utilities (markdown parsing, formatters)
│   └── styles/            # Tailwind CSS configuration and custom styles
├── content-collections.ts # Content config, if the template uses content-collections
└── vite.config.ts         # Bundler config (may be rsbuild.config.ts, or legacy app.config.ts)
```

## How a request flows

1. **Route match** — the URL is matched against the generated route tree.
2. **Loader runs** — the matched route's `loader` fetches data. On SSR this runs on the server; on client navigation it runs in the browser (server work goes through `createServerFn`).
3. **Render** — the route component renders with typed access to loader data, params, and search.
4. **Streaming** — Start can render the full document and stream UI as it becomes ready. Routes can also opt into SPA or selective-SSR modes.

## What to Edit vs. What to NEVER Touch

### ✅ Safe to Edit
- **`src/routes/**`** — add or modify pages and layouts.
- **`src/components/**`** — UI components.
- **`src/content/**`** (if present) — text and content.
- **`src/config/**`** — global settings, menus, theming.
- **`src/styles/**`** — styling, subject to the generated-file caveat below.

### 🚫 NEVER Touch
- **`src/routeTree.gen.ts`** — regenerated by the TanStack Router plugin on every dev/build. Hand edits are destroyed instantly. To change routes, add or rename files in `src/routes/`.
- **Generated theme/CSS files** (e.g. `generated-theme.css`) — produced by scripts; edit the source `theme.json` instead.
- **`src/router.tsx`** — unless deliberately changing router-wide config (context, default preload, error components).

## Bundler note

TanStack Start is Vite-based, so `vite.config.ts` is **not** a reliable way to identify the framework — plenty of non-TanStack apps have one. The distinguishing artefacts are `routeTree.gen.ts` and `src/routes/__root.tsx`, plus a `@tanstack/react-start` (or `solid-start`/`start`) dependency in `package.json`. Some templates use `rsbuild.config.ts`, and older ones use `app.config.ts`.
